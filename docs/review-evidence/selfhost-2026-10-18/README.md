# Self-host polish and certificate acceptance — October 18, 2026

Status: local candidate passes the checks below. Real Let's Encrypt staging acceptance passed. Production home-server issuance, trusted HTTPS, local restart and live Link discovery pass. The maintainer’s phone reaches the dashboard over Wi-Fi, and the restarted production API returns the exact original certificate. No native release has been published by this pass.

## Candidate and changes

Final signed candidate: `homegames/dist/release-2.0.3-lnsw76`, version **2.0.3**, with the Homegames logo as its Mac app icon. It packages published Common 1.7.4, Client 0.2.1, Squish 1.5.0 and Node 24.22.0 for Darwin ARM64/x64, Linux x64 and Windows x64. Layout verification found 98 production packages, 260 assets and 33 visible games. Apple notarization, signatures, extracted ZIP and DMG quarantine/translocation launches all pass on Apple Silicon. The final checksums and release record are saved here; nothing has been published. This supersedes `release-2.0.3-xRLTIK`, the earlier previews and the October 14 signed candidate. The icon-only rebuild retains all 1,769 compared runtime JavaScript/JSON files from the signed runtime that passed production recovery.

Core now reports disabled issuance and operator-review states promptly, keeps renewal failures visible while HTTPS is serving, offers status/retry without changing settings, and resumes saved renewals immediately after startup. Retries preserve the CSR, key and request ID; shutting down during domain/CSR preparation prevents submission. Unrelated working key/certificate files remain intact on failure. Every five minutes, a background network check compares the served certificate with the current network hostname. A changed public IP prepares a separate certificate and offers a host-controlled restart; it does not swap a running session to another hostname. Per-network requests retain their IDs/keys across moves and operator review. Discovery advertises HTTPS only when the actual served certificate matches its observed network. Lost-key recovery and re-enabling discovery with an old certificate are covered as well.

The deployed Link upgrade exposed a string-valued `HOME_PORT` registration: Core now sends a validated integer. Policy-rejected connections also retain exponential backoff until they stay connected through a heartbeat. The certificate browser harness enforces the deployed port type, so this mismatch cannot silently pass its fixture again.

The native builder skips the two explicitly hidden historical dynamic-metadata fixtures while rejecting malformed visible or explicitly selected games. The smoke verifier resolves stable game keys consistently with the dashboard. The offline browser harness uses the curated catalog and checks the default-off unsandboxed-game option through the real settings UI. Runtime cache replacement is now atomic, so a builder running from that Node executable cannot corrupt its own mapped binary during a rebuild.

The API staging checker isolates its database, account key and home-server keys; forces the staging directory; submits duplicate requests; validates two different keys on one network; and checks restart retrieval, ownership and DNS cleanup. A completed request with unfinished cleanup is recovered using the operator CLI before starting the test runner. DNS cleanup now allows up to two minutes for Route 53 propagation rather than fifteen seconds.

The maintainer chose one HTTPS server computer per public network for this release. Link now reserves the network hostname for that LAN address, rejects a conflicting registration before advertising it or writing DNS, and retains reservations while disconnected owners have unfinished DNS writes. Plain HTTP registrations never write the HTTPS A record. Multiple ports on the same LAN address do not conflict. A blocked host displays a clear explanation and a host-only retry; automatic retries occur every thirty seconds. The selector no longer sends guests to HTTP URLs for HTTPS servers still provisioning. Environment-controlled ports display their effective values and are read-only in Settings; ephemeral listeners advertise the actual bound port.

Common 1.7.4 is published and installed. All 39 registry JavaScript files match the reviewed Common source, and Core and the launcher pin it in their dependency graphs. Docker preparation now uses the installed Core production dependencies, so downloaded apps no longer require sibling checkouts or a missing Common lockfile. Runtime contents determine the image tag; updates build their own image, while running containers retain theirs. Docker availability is checked again on each launch; failed builds can retry, and failed container starts are removed before reporting the error. The game API waits for a ready server instead of reporting success for a container that never opened its WebSocket. Runtime/code mounts are read-only, Linux capabilities are dropped and no-new-privileges is set. The first image build downloads the Node base image.

## Remaining gates

- The shared EC2 role still has broad Route 53 access. Applying the restricted certificate policy must account for other services on that role.
- Physical public-IP changes and router DNS behavior still need acceptance; the local CA/browser suite verifies prepared-certificate recovery and a host-controlled restart.
- A future natural production renewal has not been observed; renewal/hot replacement and recovery are covered by the isolated CA/browser tests, while real staging validated issuance and restart retrieval. The current production test validates one physical home server, not multiple LAN machines behind one NAT.
- One HTTPS computer per public network is the accepted release limit. Distinct server keys are supported, but simultaneous HTTPS on different LAN computers is intentionally refused. Physical multi-computer handoff and shared-public-IP/CGNAT environments have not been field-tested.
- Clean Windows/Linux/Intel Mac checks remain. The final signed/notarized ZIP and DMG, quarantine/translocation launches and Docker execution pass on this Apple Silicon Mac. Four packaged runtimes alone do not prove platform support.
- Broader physical-browser/network matrix, long-running relay sessions and load/cost limits remain in the main launch plan.
