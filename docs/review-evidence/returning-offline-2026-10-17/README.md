## Deployment acceptance

Serve HTML and worker scripts with revalidation (`Cache-Control: no-cache`, or equivalent). Revalidate mutable bare asset URLs too. If a CDN is used, its cache key must include the new `v` query parameter on CSS/JS; hashed runtime filenames may be immutable. Deploy the complete generated output together. Worker integrity checks reject incomplete or mixed releases, but do not substitute for verifying real hosting headers and CDN behavior.

On the deployed site, repeat the old-profile → new-release test without clearing site data. Also test actual iOS/Android installation, storage pressure/eviction, and the WAN/TURN network matrix. WebKit automation validates browser-engine behavior, not the physical mobile install UI or mobile OS storage policies. Previously downloaded standalone HTML retains its embedded player until replaced.

Initial harness failures involved outdated toolbar/menu selectors, asynchronous editor startup and mobile layout expectations; these were corrected without weakening content, persistence or isolation assertions. Actual defects fixed in this step were shell/cache replacement, stale public assets, unavailable runtime upgrade fallback, backup/conflict recovery, an asset-picker race and copy cancellation/retry handling. The logs here are the final passing runs.
